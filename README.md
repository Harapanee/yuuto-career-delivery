# yuuto-career-delivery

Instagram **@yuuto.career** のリールを自動投稿する配信リポジトリ。

制作は別の private リポジトリで行う(分析データを公開しないため)。
ここに置くのは **投稿予定・投稿済み記録・投稿スクリプト**だけ。動画は Releases に置く。

```
[private] 制作                     [public] このリポジトリ
  動画・キャプション・分析データ  →   GitHub Actions(cron)+ 投稿スクリプト
                                     schedule.json  投稿予定
                                     state.json     投稿済み記録
                                     Releases       動画とサムネイル
```

## 投稿スロット
**1日2本(12:00 / 19:00 JST)**

| ジョブ | cron (UTC) | JST | 役割 |
|---|---|---|---|
| prepare | `0 15 * * *` | 00:00 | その日の分のコンテナを事前作成する。**前倒し禁止**(日付が前日になる) |
| publish | `56 2 * * *` | 11:56 | 12:00 の回。`media_publish` だけを撃つ |
| publish | `56 9 * * *` | 18:56 | 19:00 の回 |

**cron を予定時刻の4分前に置いてある。** GitHub Actions の cron は数分〜30分遅れ、
毎時 `:00` は世界中の cron が集中して最も遅延しやすい。遅延は後ろにしか動かないため、
起点を4分前にして吸収する。対象の選定は「予定時刻との差の**絶対値**が±90分以内」なので
前倒し起動でも正しく動く。

> **cron が無い時刻は schedule.json に書いても永久に投稿されない。**
> 新しいスロットを足すときは cron の追加を忘れないこと。

## 安全装置
| 項目 | 実装 |
|---|---|
| 二重投稿の防止 | `state.json` による冪等性。投稿は取り消せないので回復不能 |
| 記録の破損防止 | tmp + `os.replace` のアトミック書き込み |
| 取りこぼしの暴発防止 | 予定時刻から±90分を超えたら何もしない |
| 失敗を成功と記録しない | 公開が成功したあとにだけ記録を更新する |
| secrets の漏洩防止 | **`pull_request` トリガーを付けない**(public なのでフォークから触れられる) |

## Secrets
| 名前 | 中身 |
|---|---|
| `IG_ACCESS_TOKEN` | システムユーザー `bizbot` のトークン。**`EAA...` で始まる**(検証済み) |
| `IG_USER_ID` | **17841437790694307**(@yuuto.career) |

**トークンは 2026-10-29 00:30 JST に失効する。**更新手順は制作リポジトリの `HANDOFF.md` 冒頭。

**トークンの先頭を必ず確認すること。**
`EAA...` = Facebook Login → ホストは `graph.facebook.com`(このリポジトリはこちら)
`IGAA...` = Instagram Login → ホストは `graph.instagram.com`
食い違うと `Invalid OAuth access token`(code 190)が返る。**失効エラーと紛らわしいが別物。**

## 本番投入の前に必ずやること
1. **1本だけ**で通しを確認する(全件投入しない)
2. **同じ実行を2回叩いて二重投稿しないことを確認する**
3. **CI 上で1本通す。**手元から実行すると CI は一度も API を叩かないまま緑になり、
   設定ミスがすり抜ける(前回それで本番に不具合が入った)
4. 投稿後、実際にアプリで音源・サムネイル・キャプションを見る
